# Tags Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make tags count in search ranking, make the tag vocabulary visible to Claude and the user, and add any-of tag matching.

**Architecture:** Tags join the generated `fts` column (weight A) through a new goose migration, and join the embedded document text through `memory.DocumentText`. A new `TagCounts` repository query backs a `memory_tags` MCP tool, a `memorable tags` command, and one preload line. `memory.Filter` gains `TagsAny`, mapped to `tags && $n`.

**Tech Stack:** Go, PostgreSQL 17 with pgvector and pg_trgm, goose v3 (embedded SQL migrations), pgx v5, the official MCP Go SDK, cobra, testify.

**Spec:** `docs/superpowers/specs/2026-11-15-tags-design.md`

**Base:** this plan targets the code on `feat/web-ui` (`internal/adminops`, and the `Passive`, `Explain`, and `Project` fields on `SearchRequest`). Execute it on a branch from `main` after `feat/web-ui` merges, or from `feat/web-ui` if that merge is still pending.

## Global Constraints

- Tags: max 10 per memory, each `^[a-z0-9-]{1,40}$` (`internal/memory/validate.go`); unchanged.
- The `fts` weights are title A, tags A, and content B. Text search config is `'english'`.
- The embedded text is `title: <title> | tags: <a>, <b> | text: <content>`. The `| tags: …` segment is omitted when a memory has no tags, so untagged memories keep the exact current string `title: <title> | text: <content>`.
- `content_hash` stays title and content only; tags do not affect dedupe.
- The preload tag line lists the top 20 tags by count, in the format `Tags in use: a (12), b (7)`. It is omitted when no tags exist.
- Goose migration version `2` is the Go embedding migration (`internal/store/migrate.go:28`), so the new SQL migration is `00003`.
- Unit tests stay Docker-free (`make test`). Store behavior is tested with `//go:build integration` tests (`make test-integration`).
- English only, no Claude attribution in commits, conventional commit messages as in `git log`.

## Review Focus

1. **A memory whose only change is its tags.** It must be re-embedded through every path: `Service.Update`, `Service.Restore` of a version with different tags, profile updates in `adminops`, and the worker reading a queued job. The worker reads `memory_versions.tags`, not the live row.
2. **Mixed-case or spaced tags in search and list filters** (`--tag Go`, `tags: ["CI"]`). They are normalized like writes, so they match the stored `go` and `ci` instead of silently matching nothing.
3. **Profile memories.** The `fts` migration applies to `mem_profile.memories` too, and `TagCounts` includes profile tags.
4. **Untagged memories' embedding text is byte-identical** to the current format, so no re-embed is needed for them and their ranking does not change.
5. **Normalization that produces an invalid or duplicate tag** (`"C++"` becomes `"c++"` and is still invalid; `"Go"` and `"go"` collapse to one). Writes reject the first with the existing validation message and accept the second as a single tag.
